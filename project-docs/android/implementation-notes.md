# Android implementation notes

Current scope: native build and runtime verification. No Play Console work,
uploads, submissions or publishing. Android emulators and ADB run only on
`jackwallner@192.168.4.25`, never on the Air.

## Calculation and content reference

`python3 scripts/sync-android-content.py` compiles the original Foundation-only
Swift calculation, insights and drink catalog sources. It exports the 20 drinks,
three default presets, 320 decay cases, eight source-aware forecast cases and
eight insight datasets. `--check` compares regenerated bytes without changing
the checked-in resources. The manifest records source hashes.

The Kotlin model files retain the Swift names and rules. Golden tests cover all
nine metric comparisons and trends, three cutoff result states, sparse and
lopsided samples, drink-name migration and age-band defaults. Direct tests cover
source selection, local midnight/DST, fractional timestamps, per-dose heart-rate
windows, workout estimates and sleep interval unions. These tests establish model
parity; they do not establish a working app or a real Health Connect integration.

Model verification on 2026-10-17: 33 JUnit tests passed, zero failures, errors or
skips, using a temporary Gradle 9.7.0 / Kotlin 2.4.20 JVM harness with JDK 17 and
the repository's model/test/resource directories. The Swift export `--check`
also passed. The complete Android project's own unit and runtime checks remain
required before declaring a release build ready.

## Health Connect mappings

Caffeine maps to `NutritionRecord.caffeine` in milligrams; the drink label maps
to `name`. Use stable client record IDs and checked persistence for the local
retry queue. A successful retry must reconcile by client ID and remove the queue
row, so process death or lost responses cannot double-log a drink. Keep pending
rows and the retry action visible. Do not overwrite a cache with empty data when
Health Connect fails or permission is revoked.

Sleep maps to `SleepSessionRecord` stages. Map measured sleeping/light/deep/REM
stages to asleep, awake stages to awake, and the session envelope to in-bed.
An envelope without measured sleep is insufficient for a cutoff night. Merge
overlapping sleep intervals, require at least three hours, group after-midnight
sleep with the preceding caffeine day, and preserve the Swift latency guard.
The pure `SleepMath` model owns those rules.

The remaining types map to resting heart rate, HRV RMSSD, respiratory rate,
oxygen saturation, steps, active calories, heart-rate samples, exercise starts
and weight. Android HRV is RMSSD, while iOS reads SDNN. The Android label must
name RMSSD and must never describe it as the same measurement. Age and biological
sex have no direct Health Connect equivalents; do not claim to have read them.

Request caffeine read/write independently from optional body reads. Denial of
body permissions must not affect logging or forecasts. Handle partially granted
body permissions independently. Consume every page of raw records. For steps and
other cumulative measures, prefer Health Connect aggregation to avoid counting
overlapping sources twice.

Historical reads are restricted by default to 30 days before first permission.
Request the history permission only when the feature is available and needed;
otherwise bound the read and explain available history. On Android 14+, an app's
own records have no historical limit. Preserve owned records and cache rather
than silently returning an empty 90-day view after a permission error.

## Product parity

Read the iOS views and the three applicable rules before implementing screens.
Keep the five onboarding stages with a fixed primary-button/footer frame and
four tabs: Now, Cutoff, Timeline, Upgrade (Caffeine+ for members). Every quick
drink opens the editable forecast preview before saving. Own entries use the
same sheet for editing; external entries cannot be edited.

The cutoff verdict is free. It needs 21 measured nights and must retain a real
"no measurable difference" result. Before enough history exists, show the iOS
fixed worked example explicitly marked "EXAMPLE OF THE FINDING - NOT YOUR DATA".
Never invent a finding or confuse an example with the user's records.

Metric comparisons, age-based starting half-life, intake per kilogram, 90-day
history/trends, editing the three presets and the bedtime reminder are Caffeine+.
Free users keep logging, forecasts, preview, source controls and seven days of
history. Lapsed members retain their saved preset values. A locked 30/90-day
range must show a lock rather than seven days under the longer range label.

Use the existing RevenueCat project and `Caffeine+` entitlement. Product IDs are
`com.jackwallner.caffeine.monthly`, `com.jackwallner.caffeine.yearly` and
`com.jackwallner.caffeine.pro.lifetime`. Debug uses Test Store and optimized QA
uses no SDK key. Keep Restore, Terms and Privacy visible in every paywall state.
No early trial pitch before membership resolves, and trial disclosure must use
the real eligible offer. All displayed levels are modeled estimates, never
measurements, safety thresholds or claims that caffeine caused a sleep change.
